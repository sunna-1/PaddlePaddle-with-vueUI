# 路况分析模块技术文档

## 概述

路况分析模块是本系统的核心智能模块，负责从车载驾驶人视角视频中提取多维度交通指标，并综合判断道路通行状态为**畅通**、**缓行**（轻度拥堵）或**拥堵**三类。

由于系统仅基于视频图像进行分析，没有硬件传感器、GPS或车辆实际速度等外部数据支撑，路况判断面临本质性挑战。本模块采用**混合方案**：以详实的数据统计展示为主体，辅以低置信度参考判断，为用户提供决策参考而非确定性结论。

## 架构设计

### 数据流

```
视频输入 → PaddleDetection Pipeline → 检测数据JSON → app.py 分析模块 → 前端展示
              (PPYOLOE-L + ByteTrack)    (精简格式)    (多指标计算+判断)
```

### 核心组件

| 组件 | 文件 | 职责 |
|------|------|------|
| 检测数据导出 | `PaddleDetection/deploy/pipeline/pipeline.py` | 在PP-Vehicle处理循环中逐帧收集检测数据，导出为JSON |
| 数据分析引擎 | `app.py` → `analyze_from_detection_json()` | 读取JSON，计算车辆密度、面积、速度、跟踪等指标 |
| 路况判断引擎 | `app.py` → `_judge_traffic_status()` | 基于多指标加权投票进行路况参考判断 |
| 前端展示 | `frontend/src/views/AnalysisPage.vue` | 数据面板、判断因素、趋势图表 |

## 检测数据导出

### Pipeline改造

在PaddleDetection的PP-Vehicle pipeline主循环中注入数据收集逻辑，将每帧MOT检测结果导出为JSON文件。

**导出格式**（精简版，减少IO开销）：

```json
{
  "video_info": { "width": 1024, "height": 576, "fps": 30, "total_frames": 166 },
  "frames": [
    { "fid": 0, "n": 9, "v": [[1, 23.5, 89.1, 67.3, 210.5], ...] },
    { "fid": 1, "n": 0, "v": [] }
  ]
}
```

每条车辆记录为数组格式 `[track_id, xmin, ymin, xmax, ymax]`，省略了分析不需要的 `class_id` 和 `score` 字段。JSON使用紧凑序列化（`separators=(',', ':')`），无缩进。

**关键改造点**：

1. 空帧也需收集（`mot_res['boxes']` 为空时在 `continue` 前追加记录）
2. 使用 `video_fps` 变量而非被后续覆盖的 `fps` 变量
3. JSON导出在视频写入器释放后执行，不影响处理流程

### 中文文件名处理

`werkzeug.utils.secure_filename()` 会剥离中文字符，导致 `secure_filename("畅通素材.mp4")` 返回 `"mp4"`，使所有中文命名文件互相覆盖。使用UUID生成安全文件名：

```python
def generate_safe_filename(original_filename):
    ext = '.' + original_filename.rsplit('.', 1)[1].lower() if '.' in original_filename else ''
    return str(uuid.uuid4())[:8] + ext
```

## 数据分析引擎

### `analyze_from_detection_json()` 核心指标

#### 1. 车辆密度

| 指标 | 计算方式 | 说明 |
|------|---------|------|
| `avg_detections_per_frame` | 总检测数 / 总帧数 | 平均每帧出现的车辆数 |
| `max_concurrent` | 各帧车辆数最大值 | 画面中同时出现的最大车辆数 |
| `min_concurrent` | 各帧车辆数最小值 | 画面中同时出现的最小车辆数 |

#### 2. 车辆面积占比

| 指标 | 计算方式 | 说明 |
|------|---------|------|
| `avg_vehicle_area_ratio` | 各帧车辆面积总和 / 画面面积 的均值 | 反映画面中车辆占据的空间比例 |
| `max_vehicle_area_ratio` | 各帧面积占比最大值 | 峰值车辆密度 |

面积占比的计算公式：

```
帧面积占比 = Σ(车辆框面积) / (画面宽度 × 画面高度)
```

#### 3. 车辆速度（像素位移）

**良好跟踪筛选**：仅使用跟踪帧数 >= 3 的车辆计算速度，排除1-2帧的闪现噪声车辆。

| 指标 | 计算方式 | 说明 |
|------|---------|------|
| `avg_pixel_speed` | 良好跟踪车辆的帧间位移均值 | 像素/帧 |
| `max_pixel_speed` | 最大帧间位移 | 像素/帧 |
| `stationary_vehicle_ratio` | 速度 < 0.5 px/帧的车辆占比 | 反映停滞车辆比例 |

帧间位移计算：

```
displacement = √(Δx² + Δy²) / Δframe
avg_speed = mean(displacements_per_track)
```

#### 4. 画面区域分析

将画面按水平中线分为上下两半：

- **下半部分**：更接近自车，反映前方实际路况
- **上半部分**：对向车道或远景，对路况判断干扰大

| 指标 | 计算方式 | 说明 |
|------|---------|------|
| 近处车辆比例 | 下半屏唯一track数 / 总唯一track数 | 拥堵时周围车辆多，比例高 |
| 下半屏速度 | 下半屏良好跟踪车辆的速度统计 | 更反映同向车流 |

车辆归属判断：计算每辆车在所有帧中的平均中心y坐标，若大于画面高度/2则归为下半屏车辆。

#### 5. 密度分布统计

基于**面积占比**（而非车辆数）判断每帧的路况状态：

| 面积占比 | 帧状态 |
|---------|--------|
| < 5% | 畅通帧 |
| 5% - 15% | 缓行帧 |
| >= 15% | 拥堵帧 |

最终输出三种状态的帧占比百分比。

## 路况判断引擎

### 核心设计思路

驾驶视角视频的特殊性在于：即使道路畅通，画面中仍然会出现大量车辆（对向车道、远景车辆等）。因此车辆密度指标在区分畅通与拥堵时**区分度极差**。

通过实际数据分析发现的关键差异：

| 指标 | 畅通素材实测 | 拥堵素材实测 | 区分度 |
|------|------------|------------|--------|
| 平均车辆数/帧 | 9.13 | 12.22 | **差** |
| 车辆面积占比 | 2.62% | 23.03% | **极强** |
| 近处车辆比例 | 2% | 26% | **强** |
| 良好跟踪车辆速度 | 3.72 px/帧 | 3.30 px/帧 | 差（对向车干扰）|

基于此，判断逻辑以**面积占比**和**近处车辆比例**为核心指标，速度指标因对向车辆干扰而降权。

### 五指标加权投票

| 指标 | 权重 | 畅通阈值 | 缓行阈值 | 拥堵阈值 |
|------|------|---------|---------|---------|
| 车辆面积占比 | 4.0 | < 5% | 5% - 12% | >= 12% |
| 近处车辆占比 | 3.0 | < 5% | 5% - 10% | >= 10% |
| 稳定跟踪车辆速度 | 1.0 | > 4.0 px/帧 | 1.5 - 4.0 | < 1.5 |
| 稳定车辆静止占比 | 1.0 | < 15% | 15% - 35% | >= 35% |
| 最大同帧车辆数 | 1.0 | < 5 | 5 - 10 | >= 10 |

### 极强信号覆盖机制

当面积占比 >= 15%时，该指标权重自动提升至 **8.0**，确保面积占比极高时无论速度指标如何，都能正确判定为拥堵。这是因为在拥堵场景中，对向车道的快速车辆会使得速度指标偏高，产生误导。

### 投票规则

1. 各指标按阈值判定为 畅通/缓行/拥堵 信号
2. 信号乘以对应权重累加到各类别得分
3. 判定逻辑：
   - 缓行得分 > 畅通得分 且 > 拥堵得分 → 缓行
   - 畅通得分 > 拥堵得分 → 畅通
   - 拥堵得分 > 畅通得分 → 拥堵
   - 否则 → 缓行

### 置信度评估

```
dominant_ratio = max(smooth_score, slow_score, congested_score) / total_weight

>= 65% → 高
>= 45% → 中
< 45%  → 低
```

## 前端数据展示

### 数据面板结构

1. **概览卡片**：检测车辆总数、唯一车辆数、平均每帧车辆、路况参考判断（含置信度标签）
2. **详细指标**：车辆密度、车辆位移、跟踪时长、车辆面积（2×2网格）
3. **判断因素分析**：各指标的值和信号（绿色畅通/黄色缓行/红色拥堵）
4. **出行建议**：基于路况的参考建议
5. **趋势图表**：车流密度趋势（折线图）、车辆位移趋势（折线图）、路况占比（环形图）

### 空态展示

未识别视频前，所有数据模块均已展示，数值显示为 `--`，判断因素区显示骨架占位块，图表区显示空占位符。

## 已知限制

1. **无实际速度数据**：所有速度指标基于像素位移，无法转换为真实车速，不同分辨率/距离的像素速度不可比
2. **对向车辆干扰**：驾驶视角中无法区分对向车道车辆，速度指标可能被对向快车拉高
3. **短跟踪噪声**：1-2帧的闪现跟踪缺乏速度信息，虽然已排除但仍影响密度统计
4. **场景依赖**：判断阈值基于有限测试素材调优，不同道路类型（高速/市区/隧道）可能需要不同阈值
5. **置信度提示**：由于上述限制，系统始终明确标注置信度，并在置信度低时给出警告提示
